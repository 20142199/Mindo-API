# Mindo referral API

All routes below require `Authorization: Bearer <access_token>` and return the standard Mindo response envelope.

## Registration behavior

`POST /api/v1/investor/auth/register` accepts the optional `ref_by` field:

```json
{
  "full_name": "Nguyễn Văn An",
  "email": "an@example.com",
  "password": "Mindo123!",
  "confirm_password": "Mindo123!",
  "accept_terms": true,
  "ref_by": "MDABCDEFGH"
}
```

- A normal `MD...` referral code links the new F1 account to its direct F0 by immutable user ID.
- An unused `SYS...` code makes the new account a branch root. System codes are generated by Admin, are disabled as soon as they are claimed, and can only be used once.
- Every new account receives its own unique `referral_code` in the registration and login user payload.

## Investor referral dashboard

`GET /api/v1/investor/referrals/dashboard`

The response contains the current user's referral code, direct-referral count, direct reward total, current configured rates, and recent reward entries. For a branch-root account it additionally returns:

- `is_branch_root: true`
- `system_code`
- `downline_count`: every descendant, not just direct F1 accounts
- `downline_sales_vnd`: completed order value from the whole branch
- `branch_commission_vnd`: earned branch reward total

## Reward settlement

On each completed internal product purchase:

1. The direct F0 receives `order total × direct_rate_percent` (10% by default).
2. The nearest system-code branch root above the buyer receives `order total × branch_rate_percent` (5% by default).
3. A root can receive both rewards when the buyer is their direct F1.
4. Rewards are rounded to whole VND and credited to the beneficiary balance with separate immutable ledger entries.
5. NFT issuance, buyer debit, and all applicable rewards are committed atomically.

Rate changes only affect future orders. Historical reward rows retain the exact rate and amount applied when the order completed.

## Admin settings

Read settings with `GET /api/v1/admin/referrals/settings` (`ADMIN` or `FINANCE`).

Update future-order rates with `PATCH /api/v1/admin/referrals/settings` (`ADMIN`):

```json
{
  "direct_rate_percent": 10,
  "branch_rate_percent": 5
}
```

Both values accept decimals from 0 through 100.

## Admin system codes and branch sales

List codes and branch metrics with `GET /api/v1/admin/referrals/system-codes` (`ADMIN` or `FINANCE`). Each row includes the claimed root account, downline count, total downline sales, and branch reward total.

Create a one-time code with `POST /api/v1/admin/referrals/system-codes` (`ADMIN`):

```json
{ "label": "Đối tác miền Nam" }
```

The code itself is generated by the API. Disable or re-enable an unclaimed code with `PATCH /api/v1/admin/referrals/system-codes/:id`:

```json
{ "is_active": false }
```

Claimed codes cannot be re-enabled or reassigned.
